# Progression and economy (blueprint section D) - current logic

Code: `Assets/Scripts/Game/Progression/`. Tests: `Assets/Tests/EditMode/ProgressionTests.cs`. Spec: `Docs/design/BLUEPRINT_C_D.md` section D, `Docs/design/economy.md` section 15.

- **Data (ScriptableObjects, loaded from `Resources/Progression/`, code defaults when the asset is absent):** `UpgradeTreeSO` (costs 500/900/1500/2500/4000, +6% of the base per level, base per branch, per-vehicle overrides), `WorldGateSO`, `VehicleGateSO`, `ProgressionTuningSO` (scrap, mastery table, goal stubs, daily, weekly stub, ad limits, first-hour schedule). Assets exist in `Assets/Resources/Progression/` (menu `Road Builder/Progression/Create Data Assets`, never overwrites); code defaults apply when an asset is missing. `WorldGateSO`/`VehicleGateSO` live in their own files (Unity needs file name = class).
- **Upgrades:** levels owned are 0..5 per branch (Engine, Suspension, Ink, Boost, Shield) per vehicle key (`PlayerProfile.upgrades`). Bonus = base x 6% x level: engine 11.5 m/s -> +0.69 per level (was 0.8), suspension torque 34 -> +2.04 (was 3), ink 100 -> +6 (was 30), boost +0.08 s via `GameplayTuning.boostDurationPerLevel`. **Shield** (`UpgradeShield`, owned by `RunDirector.UpShield`): level 1+ gives one charge per run that absorbs a hit (the pickup shield is used first), then recharges in `shieldRechargeSeconds` = 45/38/31/24/18 s for level 1..5; HUD shows SHIELD while a charge is ready. Garage shows five rows. **Per-vehicle cost** = base cost x `costScales` (bicycle 0.8, race car 1.25, tank 1.5, moon rover 1.75; starting values), rounded to 10; the garage shows the selected vehicle's cost (`GameModel.UpgradeCosts`). Per-vehicle boost overrides are not read by `RunDirector`.
- **Legacy upgrade migration (B13, confirmed, tested by `ProgressionTests` and `UiQaFixTests.LegacyOneBasedUpgradeLevels_MigrateWithoutLosingPurchases`):** the old save stored 1..5 (1 = nothing bought); a vehicle's first visit converts them to 0..4 owned levels, so every past purchase still shows (old 3 = two pips lit). Nobody is reset; the old global fields are only read, never rewritten.
- **Save version 2:** old global levels (1..5) become 0..4 for any vehicle without an entry (lazy, in `UpgradesFor`). `Sanitize` migrates v1: lifetime distance = best distance, desert and night-city worlds and the selected world stay unlocked. Owned vehicles/worlds are never re-gated.
- **Scrap:** `profile.scrap`, awarded on a boss defeat (20 first / 10 repeat); `GameModel.Scrap` mirrors it; shown as `SCRAP n` under the coins on Home and Garage.
- **Mastery:** per-vehicle lifetime metres, levels 500/2000/5000/10000/20000, coins and gems paid to the profile once (mask), sticker/colour/cosmetic recorded in the mask only. Recorded at run end in `RoadGameManager.TriggerGameOver`. The older xp mastery in `MetaProgress` is untouched.
- **Gates:** `GateService` checks lifetime distance and an extra counter (`gate:<ExtraGate>` in `profile.counters`). **Counters** are fed by one hook, `ProgressionEvents.Record/RecordRunEnd` (`ProgressionHooks.cs`): monster reached (MON-EATER start), boss reached (BOS-ROB0 start), missions completed (claim), stage events completed (`EventEnded` while not ending/jumping), clean jumps (landing after air time >= `airMinSeconds`, `RunStats.cleanJumps`), survival runs (run end at `survivalRunMetres` 1000 or course finished); also vehicle goals `clean-landings`, `near-misses`. Not fed (no content yet): SurviveLava, WaterMastery, RhythmChallenge. **UI:** `GameModel.LockText` (id to requirement, built in `SyncProgressionModel`) shows on world cards and vehicle cards (badge + padlock); tapping a gated world pays and unlocks it when gates and coins allow, otherwise refuses with the requirement; vehicles with an unmet distance gate cannot be bought. Worlds absent from the table, owned worlds and free met worlds are never locked.
- **Daily:** `DailyChallenge` seed = FNV-1a of the UTC `yyyyMMdd`; vehicle, world, three events (from `dailyEventIds`, not yet matrix filtered) and 100-250 coins from `Pcg32`. The reward is drawn before the events; picks are filtered through `EventCompatibilityMatrix` (an explicit Forbid pair with an already chosen event is skipped; default-deny pairs are not, the events run one after another). Local best, one claim per UTC day (coins, 1 mastery point, 1 weekly token). Weekly is a key plus a token counter only. **UI:** Home `DAILY CHALLENGE` button (shows reward / best / done; tap claims when claimable, otherwise `StartDaily`): fixed vehicle and world (when they exist and are playable in the catalogue, the daily car is usable unowned) and `StageRunController.NewRecord(seed)` for the stage ladder; the player's picks are restored when the flow leaves the run. The listed events are informational: the ladder planner is not forced to use them yet.
- **Ads:** `IAdService` with `NoOpAdService` (release) and `EditorFakeAdService` (editor/dev builds). `AdOffers`: 2x coins 2/day, extra daily reward 1/day, revive 1 per run, never while a run is active, counters in the profile, spent only on a rewarded result. Wired into the result screen only (`WatchOffer`), three buttons labelled `OPTIONAL AD: ...`, each hidden unless `AdOffers.CanOffer`: 2x coins adds the run's coins again, revive restarts at the death distance on the same stage seed with 1 heart (`JumpRun`; stage runs only, `BeginRun(continuation)` keeps the once-per-run counter), extra daily reward needs the daily claimed. Release builds use `NoOpAdService`, so no offer shows. No SDK.
- **First hour:** `ProgressionTuningSO.firstHour` and `FirstHour.Claim`; data only.
